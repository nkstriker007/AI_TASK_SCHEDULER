# Decision log

D1–D14 and D16 are recorded in the design doc (section 14). This file records the decisions made during the build.

| ID | Decision | Rationale |
|---|---|---|
| D15 | **Research data source: LLM-only knowledge**  Research executors answer from model knowledge; web search is not used. | Groq has no built-in web-search tool on the structured-output models, so search would need a separate provider and API key. LLM-only keeps cost and rate limits predictable for E7. Report results as "model knowledge as of training cutoff", not as current facts. Revisit if E7 answers are too stale. |
| D17 | **LLM provider: Groq** (`groq` Python SDK, `GROQ_API_KEY`). Planner default model `openai/gpt-oss-120b`, overridable with `ATS_PLANNER_MODEL`. | Team choice. `gpt-oss-120b` supports Groq's strict `json_schema` mode, which guarantees the plan's shape. |
| D18 | **Strict-mode schema is a relaxed copy.** `llm.LLM_PLAN_SCHEMA` makes every field required and nullable (Groq strict rules), leaves out length/pattern/count limits and `sim_subplan`, and the output is normalized (nulls dropped) and then run through the full validator. | Strict mode doesn't guarantee the finer constraints. The validator stays the only judge of validity (design doc 4.4). A test checks the LLM schema against the strict rules. |
| D19 | **Plan-level extensions frozen with contract #1:** `hints.expected_fanout`, `hints.sim_subplan`, and the `Subplan`/`SubplanTask` models (local IDs `s1…`, no nested expand, ≤ 20 tasks). | The design doc's Day 1 joint hour includes the expand type and subplan model, and freezing them now avoids a contract change on Day 6. See `docs/contract.md`. |
| D20 | **LLM worker: one Groq call per attempt, no SDK retries.** `LLMExecutor` uses `ATS_EXECUTOR_MODEL` (default `openai/gpt-oss-120b`), `max_retries=0`, and a request timeout equal to the time left before `deadline_ms`; it refuses to call once the deadline has passed. Dependency results go into the user message in task-number order. | Retries and back-off belong to atsd (8.6), which sees the attempt history; SDK retries would hide failures and overrun the deadline atsd owns (8.7). |
| D21 | **Sim expand returns a canned 2-task Subplan.** `SimExecutor` answers an expand task with `s1…sN` research tasks (N = 2), `result_kind: "subplan"`. A plan's `hints.sim_subplan` is not used, because `TaskMessage` doesn't carry it. | Lets atsd's splice path be exercised on `tasks:sim` without an LLM. If atsd should splice the fixture's own subplan, contract #2 needs a field for it. |
| D22 | **Worker order of operations.** Publish `task_started`; skip with retryable `task_failed` if `deadline_ms` has passed; if the result key already exists, report `task_completed` with `committed: false` without re-running; otherwise read inputs (missing → retryable), execute, `SET NX`, report. XACK is always the last step, and entries idle for more than 30 s (`--claim-idle-ms`) are taken over with XAUTOCLAIM. An unparseable message gets a permanent `task_failed` when its `attempt_id` can be recovered and is otherwise acknowledged and dropped. | A crash at any point leaves the entry pending, so another worker finishes it, and the write-once key makes the re-run safe: an attempt may run twice, a result is recorded once (8.5). |
| D23 | **Result values.** The key holds the executor's output verbatim: text for outputs, the Subplan as JSON for expand tasks. `result_kind` is derived from the task type (expand → `subplan`), so a duplicate report needs no extra key. Keys have no TTL. | Keeps contract #2's single result key per task. Expiry is a request-lifecycle decision for atsd. |
